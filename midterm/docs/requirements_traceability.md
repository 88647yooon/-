# 요구사항 추적표

The Family 통합 정보시스템(학번 202211207)의 요구사항(Requirement ID)을 그 요구사항을 구현한 API와 JS 파일에 연결한 표입니다.

- 기준 요구사항: `requirements_spec.md`의 58개 (기능 FR 23, 업무 규칙 BR 10, 데이터 DR 6, REST API AR 8, 비기능 NFR 5, 기술 제약 CR 6)
- API와 요구사항의 연결은 [API 목록표](api_catalog.md)의 요구사항 열, Swagger 설명 맨 앞의 [ ]와 같습니다. `(#번호)`는 API 목록표의 번호입니다.

## 구현 위치

그 API(요구사항)를 구현하는 데 사용하는 JS 파일입니다. 경로는 `midterm` 폴더 기준입니다.

- API 행: 라우트 파일(`routes/`), 컨트롤러 파일(`controllers/`), 서비스 파일(`services/`)
- 업무 규칙(BR) 행: 위 파일과 함께, 규칙을 검사하는 파일(예: `services/assignmentRules.js`)이나 규칙을 지키는 조회·이력 저장 파일(`models/`)
- 모든 API가 공통으로 쓰는 `middlewares/authenticate.js`(인증), `middlewares/authorize.js`(권한), `middlewares/validate.js`(입력 검증), `middlewares/errorHandler.js`(오류 응답)는 각 API 행에서 생략하고 BR-09, AR, NFR 행에 적었습니다.

## 확인방법

모든 확인은 Swagger UI(http://localhost:9800/api-docs)에서 API를 직접 실행하고 응답을 보는 방법으로 적었다. 각 칸의 번호 순서대로 실행한다.

- **로그인**: "POST /api/auth/login을 soldier1 / Family2026!로 로그인한다"는 `POST /api/auth/login`에서 [Try it out]을 누르고 Request body를 `{"username": "soldier1", "password": "Family2026!"}`로 바꿔 [Execute]를 누르는 것이다. 응답의 `data.accessToken` 값을 큰따옴표 없이 복사해 오른쪽 위 [Authorize]에 넣는다. 계정을 바꿀 때는 [Authorize]에서 Logout을 누른 뒤 새 토큰을 넣는다. 계정 목록은 [기능 확인 방법](requirements_check.md) 1장에 있다.
- **값 넣기**: Parameters는 URL에 들어가는 path 값(`{taskId}` 등)과 query 값(`page` 등)을 넣는 칸이고, Request body는 보낼 JSON을 넣는 칸이다. 넣을 값이 없는 API는 Parameters에 No parameters가 나온다.
- **결과 보기**: [Execute]를 누르면 아래 Server response의 Code에 상태 코드가, Response body에 응답 JSON이 나온다. 그 아래의 Responses 표는 응답 형식 설명이라 실행 결과가 아니다.
- **규정 번호**: 규칙 위반으로 거부되면 `error.code`에 `BR-02` 같은 규정 번호가 나온다. 403 거부는 `error.code`가 `FORBIDDEN`이고 규정 번호는 `error.details.rule`에 나온다.
- **앞 단계의 값**: "2번 응답의 id"는 그 칸의 2번에서 실행한 API 응답의 `data.id` 값이다. 평가·이의 제기·평판 기록·감사 로그의 id는 MongoDB 문서 id라 실행할 때마다 바뀌므로, "응답 data의 첫 번째 id를 복사한다"는 단계에서 복사한 값을 다음 단계에 넣는다.
- **시각 값**: `D+1T13:00`은 시드를 넣은 날의 다음 날 13:00(한국 시간)이다. 시드를 넣은 날이 2026-10-23이면 `2026-10-24T13:00:00+09:00`으로 넣는다. `D+0`은 시드를 넣은 날이고, `NOW+1h`, `NOW+5m`은 지금부터 1시간, 5분 뒤의 시각이다.
- **데이터**: 각 칸은 시드 데이터만 있는 상태에서 시작한다. 앞의 확인으로 데이터가 바뀌었으면 서버를 `node app.js --reset`으로 다시 시작한다. 강북 정기 순찰은 시드를 넣은 날의 다음 날 10:00~12:00, 물품 운송은 지금 진행 중, 강남 정보 수집은 전날 완료된 업무다.
- **Swagger 밖에서 보는 행**: BR-09·NFR-01의 "웹 화면" 행과 CR-02는 웹 화면이라 브라우저에서, CR-01·CR-05·CR-06은 실행 환경과 코드 구조라 터미널과 폴더에서 확인한다. AR-01·AR-02·AR-06~AR-08·CR-04는 Swagger UI 화면 자체를 보는 방법이다.
